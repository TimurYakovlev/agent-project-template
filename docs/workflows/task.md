# От просьбы к результату

1. Определи результат и границу. Для короткой задачи достаточно пары предложений.
   Для нескольких этапов используй `templates/task.md` и существующий документ задачи.
2. Прочитай маршрут области из `project.json`, её инструкции и источники.
   Если подходящей области нет, выполни разовую задачу без перестройки проекта.
3. Проверь доступный способ исполнения. Недостающие сведения уточни только
   там, где они меняют результат; остальную часть продолжай.
4. Выполни работу по выбранному workflow. Передай отдельному исполнителю
   `docs/roles/executor.md` и компактный пакет, когда делегирование нужно задаче.
5. Запусти проверки области. При обязательной независимой проверке передай
   точный результат другому агенту по `docs/roles/reviewer.md`.
   Исправляй замечания в исходных границах и проверяй изменённую версию.
6. Сверь результат с последним поручением и отказами. Доставь его согласованным
   способом. Укажи проверенный уровень: локальный файл, принятый результат,
   отправленное сообщение или проверенная публикация.
7. Перечитай трекер перед записью; обнови только затронутую задачу.
   Запиши в `NOW.md` три пункта с датой: результат, следующий шаг, вопросы.
   Простой ответ без работы не требует записи.

`work/tasks.json` — JSON-массив. Запись содержит уникальный `id`, `title`,
`status` (`todo`, `doing`, `blocked`, `done`) и `source` —
ссылку на задачу или краткое основание. Закрытие требует проверенного результата
или прямого решения пользователя. Не создавай параллельный трекер,
если в проекте уже есть действующий источник.
