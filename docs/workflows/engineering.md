# Разработка

Прочитай README затронутого приложения, локальные инструкции и вызывающий код.
Назови ожидаемое поведение, границы правки, данные и внешние вызовы.

Найди существующее решение перед новой зависимостью. Сохрани архитектуру
приложения и обработку ошибок. Для бага сначала воспроизведи сбой.
Проверяй новую логику значимыми сценариями, включая отказ или повторный вызов,
если затронуты платежи, права доступа, отправки и изменение данных.
Косметическая правка не требует искусственного набора тестов.

Проверки выполняй с временными данными и подменой внешних сервисов, если
живое действие не входит в поручение. Назови фактически запущенные команды
и ограничения. Пройденные модульные тесты не подтверждают внешнюю интеграцию.
Коммит, push и production deploy имеют разные статусы и полномочия.
Общий порядок сдачи и состояния — `docs/workflows/task.md`.
