# agent-project-template

Стартовый комплект для работы над проектом с Codex или Claude Code. После настройки короткая просьба должна запускать подходящий процесс: агент читает источники, выполняет задачу, проверяет результат и сохраняет точку продолжения.

Каркас нужно настроить под ваш бизнес, материалы и ограничения. Файлы с инструкциями помогают агенту соблюдать порядок работы; сами по себе они не гарантируют исполнение и не подключают внешние сервисы.

## Быстрый старт

1. Получите доступ к приватному шаблону. На GitHub нажмите **Use this template → Create a new repository**, задайте имя и выберите **Private**. Доступ к исходному шаблону есть у приглашённых участников. Новый репозиторий получает файлы шаблона без его истории изменений. [Порядок создания — в GitHub Docs](https://docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template).
2. Откройте корневую папку своего репозитория в Codex или Claude Code.
3. Напишите агенту:

   > Настрой этот каркас под мой проект. Сначала изучи существующие материалы, затем задай недостающие вопросы.

4. Ответьте на вопросы. Агент проводит интервью по 2–3 вопроса, сохраняет ответы без секретов и предлагает правила для вашего проекта. Настройка завершена после проверки файлов и пробной задачи по [процессу настройки](docs/onboarding.md).

В Codex настройку можно вызвать через `$project-setup`, в Claude Code — через `/project-setup`. Обычная просьба выше ведёт к тому же процессу. Если навык недоступен, попросите явно прочитать `AGENTS.md` и `docs/onboarding.md`.

## Первая задача

После настройки можно написать:

> Подготовь письмо клиентам о новом сроке доставки. Возьми условия из материалов проекта, проверь даты и сохрани черновик для моего согласования.

Агент должен выбрать процесс для текста, прочитать условия, уточнить существенные пробелы, подготовить и проверить черновик. В конце он указывает результат и оставшиеся ограничения, обновляет состояние работы. Отправка письма требует отдельного поручения.

## Проверка каркаса

Для чтения инструкций агентом отдельные библиотеки не нужны. Для проверки файлов нужен Python 3.11 или новее. Из корня репозитория:

```shell
python -X utf8 scripts/check.py
python -X utf8 -m unittest discover -s scripts -p "test_*.py" -v
```

На Windows используйте рабочий Python. Если команда `python` открывает магазин или не запускается, попробуйте `py -3` вместо `python` и проверьте версию.

Первая команда проверяет структуру, локальные ссылки, JSON, входы навыков и простые признаки секретов. Вторая запускает тесты проверяющего скрипта. Это команды для запуска, а не подтверждение уже выполненной проверки. Успешный результат не заменяет проверку вашей задачи и аудит безопасности. Тот же набор проверок описан в [GitHub Actions](.github/workflows/check.yml).

## Перенос в существующий проект

Откройте шаблон отдельно и поручите агенту сравнить его с вашим проектом. Выберите нужные части; перед изменением существующих инструкций сохраните исходники и просмотрите различия. Не копируйте каркас поверх файлов с теми же именами.

Шаблон не переносит чужие данные, аккаунты, ключи, настройки инструментов и историю Git. Подключения и доступы настраиваются отдельно. Лицензия комплекта — [MIT](LICENSE).
